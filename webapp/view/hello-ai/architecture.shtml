How the scratch pad, the panel, and the tools connect

🏗️ Architecture

Hello AI is three HTML documents. Scratch Pad is the demo. Code Examples and this page are the write-up. Each address loads its own page, the same way the other hello examples do.

📄 Three pages

The scratch pad is the textarea on /hello-ai/. This page does not have that textarea. Opening Code Examples or Architecture in this tab loads a new document. The pad you were editing stays on the Scratch Pad tab if that tab is still open. A reload of Scratch Pad restores the text baked into the HTML. There is no save endpoint and no database collection for the pad.

🧩 Who owns what

Piece Where it runs What it owns
View Browser, index.shtml The textarea, panel.create, and the adapter that reads and writes the pad
Panel Browser, AI Core The chat UI, turns, Apply cards, /help, attachments
Modules Browser, when a client tool runs readDraft and proposeRewrite. Both return a result. Neither writes the pad
Controller Server, helloAi.js Which tools exist for this scope, the server clock, the prompt fragment

🔧 The four tools

Tool Host What a call does
read_draft Client, module readDraft Returns the pad text, capped at 32 KB, plus a 160-character excerpt. The textarea stays as it is
propose_draft_rewrite Client, module proposeRewrite, proposes: true Returns a proposal. The panel shows an Apply card. Up to 3 proposals per turn. The same arguments twice in one turn are rejected
append_draft Client, adapter.executeTool, mutates: true Appends immediately. There is no Apply card. Up to 3 writes per turn
get_hello_clock Server, onAiToolExecute Returns the server time and the current username. The pad is not involved

Registration is gated on scopeType === 'hello-ai'. Another page that opens the panel does not inherit these tools, and installing the bundle does not open a WebSocket on every page.

📋 Page load

1. Browser
Requests /hello-ai/
↓
2. Server
Sends the HTML document: heading, Open chat button, textarea, and the page script.
The pad text in that HTML is the demo paragraph. Nothing is loaded from a database
↓
3. Browser
jPulse.dom.ready runs jPulse.ai.panel.create
with scopeType: 'hello-ai' and scopeId: 'demo'
↓
4. Capability
The controller's onAiToolRegister adds the four tools for this scope.
Client-host tools are on the list, so a turn on this page uses the WebSocket

📋 Read the scratch pad

1. Panel
The user sends a turn, for example from [[Read the scratch pad]]
↓
2. Server
The model calls read_draft. The server asks this tab to run it,
because the tool is host: 'client'
↓
3. Browser
Loads the readDraft module.
adapter.toolData('read_draft') returns { text, selection } from the textarea.
run() returns counts, an excerpt, and the text capped at 32 KB
↑
4. Server
The tool result goes back into the turn, so the model can use it.
The textarea is unchanged

📋 Propose a rewrite

1. Browser module
proposeRewrite.run checks the replacement text and returns
data.proposal with a preview line and payload.text.
It does not assign draft.value
↓
2. Panel
Shows an Apply card. adapter.renderProposalPreview supplies the preview line.
Several calls in one turn are several cards, up to the proposal budget
↓
3. Apply
adapter.applyProposal stores the current textarea on _undoById
and replaces draft.value with payload.text
↓
4. Undo
canUndoProposal is true only while this tab still holds that snapshot.
A reload or another tab has no snapshot, so Undo stays hidden

📋 Append, and the server clock

append_draft

append_draft has no module. The browser calls adapter.executeTool, which appends args.text to the textarea and returns the new length. The user sees the pad change. There is no Apply card.

get_hello_clock

get_hello_clock is host: 'server'. onAiToolExecute sets ctx.result to the ISO time and ctx.actor.username. The browser does not run a module, and the textarea is not read or written.

📁 File structure

plugins/hello-ai/webapp/
├── controller/
│   └── helloAi.js                 # Scope, tool list, server clock, prompt

│   └── proposeRewrite.js          # Pure proposal
└── view/
    ├── jpulse-navigation.js       # Hello World Site Demos entry
    └── hello-ai/
        ├── index.shtml            # Scratch pad and panel
        ├── code-examples.shtml
        └── architecture.shtml

✅ What to copy

  • A view that calls jPulse.ai.panel.create with a scopeType your controller recognizes
  • An adapter: toolData for reads, executeTool for a direct write, and apply / undo when a tool proposes
  • A controller on onAiToolRegister that pushes tools only for that scope
  • A pure run(data, args) module when the tool should not write by itself

Put that code in site/webapp/. Disable this plugin under Admin → Plugins to hide the demo. The panel, turns, and quota stay.

🔀 Alongside the other hello demos

The To-Do MVC demo is the same kind of site: each tab is its own .shtml document, and the browser fetches data when the page needs it. Hello AI's scratch pad is the textarea in front of you. The to-do demo's data is a Mongo collection behind /api/1/helloTodo.

The Vue.js SPA demo keeps its screens on one document and switches them in the browser. Code Examples and Architecture here are addresses you can open, bookmark, and reload on their own.
